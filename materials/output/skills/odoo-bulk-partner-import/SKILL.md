# Odoo 거래처 대량 등록

## 이 스킬이 있는 이유

이건 사람이 Odoo 화면에서 한 줄씩 손으로 치던 일을 대신하는 스킬이다. 그래서
실패 처리 방식이 스킬의 값어치를 결정한다. 사람은 20행 중 7행에서 오타를 만나면
그 행만 건너뛰고 나머지를 마저 입력한다. 7행에서 멈추고 손을 떼는 사람은 없다.

**한 행이 실패해도 절대 전체를 멈추지 않는다.** 중간에 멈추면 사용자는 "어디까지
들어갔지?"를 직접 확인해야 하고, 그게 손으로 입력하는 것보다 나쁘다. 실패는
기록하고 다음 행으로 간다. 그리고 마지막에 **등록·스킵·실패를 빠짐없이 표로**
보여준다 — 사용자가 이 표 하나만 보고 후속 조치를 판단할 수 있어야 한다.

또 하나. 이 스킬은 **쓰기 작업**이다. 조회는 틀려도 다시 하면 그만이지만 중복
생성된 거래처는 누군가 손으로 지워야 한다. 그래서 생성 전 중복 확인이 선택이 아니다.

## 절차

### 1. 입력 파일을 읽는다

엑셀(.xlsx)이면 `openpyxl`로 읽는다. CSV면 그냥 Read로 읽어도 된다.

> **한글이 깨지면 파이프를 의심할 것.** Windows 콘솔은 기본 코드페이지가 949라
> `print()`로 한글을 뽑으면 `ȸ���`처럼 깨져 나온다. 파일 내용이 깨진 게 아니라
> 출력 경로가 깨뜨리는 것이다. 스크래치패드에 UTF-8 JSON으로 쓰고 Read로 읽으면
> 멀쩡하다.

```python
import openpyxl, json
wb = openpyxl.load_workbook(<파일경로>)
out = [{'sheet': ws.title, 'rows': [list(r) for r in ws.iter_rows(values_only=True)]}
       for ws in wb.worksheets]
open(<스크래치패드>/'rows.json', 'w', encoding='utf-8').write(
    json.dumps(out, ensure_ascii=False, indent=1))
```

빈 셀은 `None`으로 들어온다. 아래 단계에서 "값 없음"과 같게 취급한다.

### 2. 컬럼을 Odoo 필드에 매핑한다

엑셀은 만든 사람마다 컬럼명이 다르다. 헤더 행을 읽고 **뜻으로** 매핑한다 —
아래 표는 자주 보이는 예시일 뿐이니, 여기 없는 이름이라도 의미가 통하면 매핑한다.

| 입력 컬럼(예시) | Odoo 필드 |
|---|---|
| 회사명 / 거래처명 / 업체명 / 상호 / 협력사명 / 고객사 | `name` (필수) |
| 이메일 / 메일 / E-mail | `email` |
| 전화 / 연락처 / 전화번호 / TEL | `phone` |
| 담당자 / 담당 / 대표자 / 성명 | `name`에 괄호로 병기 (3단계 참조) |
| 사업자번호 / 사업자등록번호 | `vat` |
| 주소 | `street` |

헤더가 아예 없고 데이터부터 시작하는 파일도 있다. 그럴 땐 열의 내용을 보고
판단한다 — `@`가 들어 있으면 이메일, 하이픈과 숫자로만 되어 있으면 전화다.
**추측으로 매핑했으면 등록 전에 사용자에게 "이렇게 읽었다"고 보여주고 확인받는다.**
잘못 매핑한 채로 20건을 만들면 20건을 다시 지워야 한다.

> **`mobile` 필드는 없다.** Odoo 19에서 `res.partner.mobile`이 삭제되고 `phone`으로
> 통합됐다. "휴대폰" 컬럼이 있어도 `phone`에 넣는다. `mobile`로 보내면
> `Invalid field 'mobile' in request` 에러가 난다.

### 3. 값을 정리한다

- **필수값 `name`이 비었으면 생성 시도 자체를 하지 않는다.** 바로 실패 목록에
  "회사명 없음"으로 올리고 다음 행으로 간다. Odoo에 빈 이름으로 보내면 에러가
  나거나, 더 나쁘게는 `false`라는 이름의 유령 거래처가 생긴다.
- **담당자는 회사명 뒤에 괄호로 병기한다** — `(주)태성정공 (오세훈)`. 담당자
  컬럼이 비어 있으면 괄호 없이 회사명만 쓴다.
- **거래처 구분** — 협력사·공급업체·공급사면 `supplier_rank: 1`, 고객·매출처면
  `customer_rank: 1`. 파일명이나 시트명에 단서가 있는 경우가 많다(예:
  `신규협력사.xlsx` → 공급업체). 단서가 없으면 사용자에게 묻는다. 둘 다 0이면
  거래처 목록 필터에 안 잡혀서 나중에 "등록했다는데 왜 안 보이지?"가 된다.
- 빈 값은 필드를 **생략**한다. `""`나 `false`를 명시적으로 보내지 않는다.

### 4. 중복부터 확인한다 — 생략 금지

**생성 호출을 하기 전에 반드시 `search_records`로 이미 있는 이름을 걸러낸다.**
Odoo는 같은 이름의 거래처를 아무 경고 없이 몇 개든 만들어 준다. 이 단계를
건너뛰면 중복 레코드가 조용히 쌓이고, 발견되는 건 한참 뒤 누군가 발주를 잘못된
쪽에 넣은 다음이다.

행마다 한 번씩 부르지 말고 이름을 모아 **한 번에** 조회한다:

```
mcp__odoo__search_records(
  model="res.partner",
  domain=[["name", "in", [<유효한 회사명 전부>]]],
  fields=["name", "email", "phone", "is_company", "parent_id"],
  limit=100,
  order="id asc")
```

돌아온 이름은 "스킵(중복)"으로 기록하고, 기존 id를 요약 표에 남긴다.

기존 레코드의 이메일·전화가 엑셀과 **다르면** 그 사실을 요약에 적고 갱신할지
물어본다. 묻지 않고 덮어쓰지 않는다 — 어느 쪽이 최신인지는 사용자만 안다.

`"in"`은 완전일치라 `(주)태성정공`과 `태성정공`을 다른 회사로 본다. 표기 흔들림이
의심되면(괄호 유무, 띄어쓰기, `㈜` vs `(주)`) 핵심어로 `ilike` 조회를 한 번 더
돌려 유사 후보를 사용자에게 보여준다.

### 5. 생성한다 — 한 행이 실패해도 계속

중복이 아닌 행만 생성한다.

```
mcp__odoo__create_record(
  model="res.partner",
  values={"name": <회사명 (담당자)>, "email": ..., "phone": ...,
          "supplier_rank": 1})
```

```
mcp__odoo__update_record(
  model="res.partner", record_id=<방금 만든 id>, values={"is_company": true})
```

> **`is_company`는 생성 두 번, 즉 create + update로 넣어야 한다.** Odoo 19는
> `create`에 담긴 `is_company`를 무시하고 개인으로 만든다. 수정에서만 반영된다.
> 이걸 빠뜨리면 회사가 전부 개인 연락처로 등록돼서 거래처 목록에 회사로 안 잡힌다.
> 생성 직후 `update_record`를 한 번 더 부르는 것이 유일한 방법이다.

에러가 나면 그 행을 실패 목록에 **사유와 함께** 기록하고 다음 행으로 간다.
사유는 Odoo가 준 메시지를 그대로 옮긴다 — "실패"라고만 적으면 사용자가 고칠 수 없다.

수십 건 이상이면 10건쯤마다 진행 상황을 한 줄 알린다. 조용히 몇 분간 도구만
호출하면 사용자는 멈춘 줄 안다.

### 6. 결과를 표로 요약한다

이 표가 이 스킬의 결과물이다. 세 부류를 **한 표에** 담아 한눈에 보이게 한다 —
따로 쪼개면 "실패가 있었나?"를 사용자가 찾아다녀야 한다.

| 회사명 | 결과 | id | 이메일 | 전화 | 비고 |
|---|---|---|---|---|---|
| (주)태성정공 (오세훈) | ✅ 등록 | 36 | sales@taesung-machine.example.com | 031-555-1101 | |
| 남광열처리 (서지훈) | ✅ 등록 | 38 | 미등록 | 052-555-1404 | |
| (주)정우정밀 | ⏭️ 스킵 (중복) | 기존 10 | — | — | 이메일·전화 엑셀과 동일 |
| *(회사명 없음)* | ❌ 실패 | — | ghost@example.com | 02-555-1505 | `name` 필수값 누락 |

표 아래에 **등록 N건 / 스킵 M건 / 실패 K건**을 한 줄로 적는다.

- 빈 값은 `미등록`으로 적는다 — 빈칸은 "값이 없다"인지 "처리를 안 했다"인지
  구별이 안 된다. (해당 없음을 뜻하는 `—`와는 다르다.)
- **실패한 행은 원본 데이터를 그대로 보여준다.** 사용자가 엑셀을 고쳐 다시
  넘길 수 있어야 한다.
- 생성한 id는 빠짐없이 적는다. 되돌릴 때 이 목록이 유일한 단서다.
- 추측으로 컬럼을 매핑했거나 `supplier_rank`/`customer_rank`를 임의로 정했다면
  표 아래에 밝힌다.

## 되돌리기

실습이나 테스트로 만든 레코드는 되돌릴 수 있어야 한다. 그래서 6단계에서 id를
남기는 것이다.

```
mcp__odoo__delete_record(model="res.partner", record_id=<id>)
```

- **이번 실행에서 생성한 id만 지운다.** 스킵된 기존 거래처는 원래 있던 것이니
  절대 건드리지 않는다. "방금 등록한 거 취소해줘"는 신규 생성분만 뜻한다.
- 지우기 전에 **어떤 id를 지울지 목록으로 보여주고 확인받는다.** 삭제는 되돌릴
  수 없다.
- 발주·견적 등이 이미 연결된 거래처는 Odoo가 삭제를 거부한다. 그럴 땐
  `update_record`로 `{"active": false}`를 넣어 보관 처리(archive)하고, 그렇게
  했다고 알린다. 목록에서 사라지므로 실무상 삭제와 같은 효과다.
- 워크숍·실습이라고 사용자가 밝혔다면 이름 끝에 `(실습용)`을 붙여 두면 나중에
  `[["name", "ilike", "(실습용)"]]`로 한 번에 찾아 정리할 수 있다. 다만 이름을
  바꾸는 것이므로 **먼저 물어보고** 붙인다.

## 하지 않는 것

- **확인 없이 기존 레코드 덮어쓰기.** 중복은 스킵이 기본값이다.
- **조회.** 등록 없이 찾기만 하면 `odoo-contact-lookup`으로 넘긴다.
- **집계.** "거래처별 발주 합계" 같은 요청은 `odoo-purchase-report`로 넘긴다.
